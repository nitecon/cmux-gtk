# Windows native preview

This experimental x86-64 build uses the same GTK workspace UI and Ghostty terminal engine as Linux, with native ConPTY shells. It requires Windows 10 version 1809 or newer, or Windows 11, and a driver supporting desktop OpenGL 4.3.

Extract the entire preview archive to a writable folder. Run `launch-cmux.cmd` to open CMUX. Keep its executables, DLLs and `share` directory together; MSYS2 is not required on the destination computer. From PowerShell in that folder, use `./cmux.exe ping` or `./cmux.exe --json list-workspaces` to check the running app. Add the folder to PATH to use `cmux` in other terminals.

Download `cmux-gtk-windows-x86_64.zip` and its `.sha256` file from the latest CMUX GitHub release for the published Windows preview. To update an extracted installation, close CMUX and run `cmux --update` (or `cmux update`) from a separate Windows Terminal. The updater downloads the complete portable bundle, checks its SHA256 and stages it before replacing the installation's managed files. Replacement runs after the updating CLI exits; check `.cmux-update.log` in the bundle folder for successful completion or a failure explanation, then run `launch-cmux.cmd`. It preserves application settings and saved sessions under `%LOCALAPPDATA%`, and leaves unrelated files in the extracted folder alone. A locked or failed replacement leaves a recoverable installation; CMUX does not kill applications or restart them automatically. Updates are explicit; there is no background polling or unattended restart on Windows.

The default shell is the Windows command prompt. A Ghostty `command` setting can select PowerShell or another native shell. CLI control uses a local named pipe restricted to the current Windows user. Configuration and application data default to the corresponding `config`, `data`, `state` and `cache` directories under `%LOCALAPPDATA%`, each containing a `cmux` directory; absolute XDG overrides remain supported.

Gateway routing and human composition use the same architecture as Linux. Launch `codex`, `claude` or another application normally. CMUX owns unfinished human text in its visible editor; plain Enter submits it, modified Enter adds a newline. Complete human messages and gateway events share one process input FIFO, independent of downstream prompt/busy state. Windows process creation times and the ConPTY-owned tree fence delivery; no provider-specific launcher or hooks are required. Ordinary agent-tools registration/task identity is independent of native terminal membership, which remains unbound unless an exact attachment is already known. Configure gateway URL, key and experimental injection consent in CMUX settings. Task selection and Windows responsibility belong to AGENTS.md/CLAUDE.md; gateway and CMUX do not assign work by OS. Live destination acceptance remains separate from CI.


Desktop notification toasts, workspace startup scripts, the Claude Teams POSIX tmux shim and automatic TCP-port attribution are unavailable in this preview. The in-app inbox and workspace attention indicators remain available. Linux command paths and externally installed browser services need Windows-compatible equivalents.

Diagnostics live in `%LOCALAPPDATA%\state\cmux` by default. Include the preview's `build.json` and diagnostic log when reporting startup problems. CI smoke evidence, when successful, is included as `smoke-result.json` and `smoke.log`. The hosted Windows runner can use an isolated software OpenGL test copy; its software driver is not included in the transferable bundle. Hardware graphics and live delegation still need validation on the destination computer.

Builds are produced from `main` and version tags by the Windows builds and releases GitHub Actions workflow using MSYS2 UCRT64, GTK4, native Rust and the Ghostty-pinned Zig version. Main builds expose the `cmux-windows-x86_64-preview` diagnostic artifact and the `cmux-gtk-windows-x86_64` portable archive artifact. Version tags publish the complete ZIP and checksum as GitHub release assets. The bundle's `build.json` identifies the exact compiled revision; `managed-files.json` records the relative paths owned by its updater. CI exercises ordinary registered clients in two native ConPTY fixtures, local multiline draft isolation, native Enter submission and peer lifecycle delivery, plus real official Codex TUIs, rendered pixels and full-bundle updater checks. Legacy hooks are negative regression triggers only and are never installed; no enrollment input is produced. These fixtures do not replace testing actual providers and hardware graphics on the destination. Windows remains an experimental portable preview, including when it accompanies a stable Linux release; there is no Windows installer.
